# Участие в AIUpdater

Ошибки и предложения принимаются через [Issues](https://github.com/TheVSAKeeper/AIUpdater/issues/new/choose).
Для крупного изменения сначала опиши задачу и ожидаемое поведение, чтобы согласовать направление до реализации.
Небольшое исправление можно прислать сразу в pull request.
В обсуждениях придерживайся [правил общения](CODE_OF_CONDUCT.md).

Об уязвимостях сообщай [конфиденциально](SECURITY.md).
Исходный код и присылаемые изменения распространяются по [лицензии MIT](LICENSE).

## Окружение

Сборка и проверки WPF выполняются на Windows. Версия .NET SDK закреплена в [global.json](global.json).
Для полного набора проверок также нужен PowerShell 7 (`pwsh`); Windows PowerShell вызывается скриптами отдельно.
Пакеты KeepShell находятся в `packages/`, а источники и сопоставление пакетов заданы в `nuget.config`.

```powershell
dotnet restore AIUpdater.slnx --locked-mode
dotnet build AIUpdater.slnx -c Release
```

## Изменения

- Соблюдай `.editorconfig` и стиль окружающего кода. Тексты интерфейса и документация написаны по-русски.
- Сохраняй независимость провайдеров: сбой одного CLI не должен стирать данные другого или молча менять выбранного агента.
- UI использует KeepShell: общие стили остаются в каркасе, представления и тема приложения – в AIUpdater.
- При изменении сценариев обновления проверяй разделение проверки, обновления и установки. Проверка не должна устанавливать программы, перезапускать их или менять окружение.
- Сохраняй локальные настройки, кэш и результаты пользователя. Изменение формата данных требует проверки чтения прежних файлов.

## Проверка

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File build/verify.ps1
```

Скрипт собирает решение, проверяет PowerShell-сценарии на подставных ответах и запускает WPF-проверки
на общем графе сервисов приложения. Привязки, навигация, настройки, перевод, ошибки и остановка операций
проверяются без обновления реальных программ.

Для изменений интерфейса приложи актуальный снимок. [Галерея](assets/screenshots/README.md#как-обновить-кадры)
работает автономно. Для изменений документации проверь ссылки, названия файлов и соответствие интерфейсу.

## Pull request

Опиши конкретную проблему, новое поведение и выполненные проверки. Если проверка недоступна в твоём окружении,
укажи это прямо. Не прикладывай токены, конфигурацию авторизации CLI и журналы с персональными данными.

Коммиты и заголовки PR оформляются по-русски, например «Исправлено сравнение версий».
Зависимости и lock-файлы изменяются вместе. Версию приложения и заметки выпуска обновляют при подготовке релиза;
правки документации сами по себе новой версии приложения не требуют.
