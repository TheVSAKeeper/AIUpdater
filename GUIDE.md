# Руководство AIUpdater

Подробности к [обзору приложения](README.md): карточки и статусы, правила обновления AI-инструментов и среды разработки, окно «Что нового», журналы, сборка, релизы и миграция окружения.

## Провайдеры и карточки

AIUpdater объединяет 17 компонентов в пяти группах. У каждого инструмента своя карточка, собственная проверка версий и отдельный сценарий обновления.

| Группа | Компонент | Что проверяется и как обновляется |
| --- | --- | --- |
| OpenAI | ChatGPT / Codex | Настольное приложение `OpenAI.Codex` (Microsoft Store / `winget`) |
| OpenAI | Codex CLI | Активная команда `codex` из `PATH` |
| OpenAI | Codex npm | Глобальный пакет `@openai/codex` в `npm root -g` |
| OpenAI | Codex плагины | Установленные плагины и кэш маркетплейсов в `~/.codex/plugins` (прямое обновление) |
| Anthropic | Claude Desktop | Настольное приложение `Anthropic.Claude` (`winget`) |
| Anthropic | Claude Code | Активная команда `claude` из `PATH` (штатный установщик или пакет владельца) |
| Anthropic | Claude npm | Глобальный пакет `@anthropic-ai/claude-code` в `npm root -g` |
| Anthropic | Claude плагины | Плагины Claude Code через `claude plugin update` (прямое обновление) |
| Google | Antigravity Desktop | Настольное приложение `Google.Antigravity` (`winget`) |
| Google | Antigravity CLI (agy) | Команда `agy` и манифест официального установщика для Windows x64 / ARM64 |
| DeepSeek | DeepSeek Harness (DSH) | Глобальный пакет `@deepseek-ai/dsh` в канале `latest` (включая RC-выпуски) |
| Разработка | Windows Terminal | Пакет `9N0DX20HK701` через источник `msstore` в `winget` |
| Разработка | PowerShell 7 | Активная команда `pwsh` и пакет `Microsoft.PowerShell` (`winget`) |
| Разработка | Docker Desktop | Настольное приложение `Docker.DockerDesktop` (`winget`) |
| Разработка | .NET SDK 10 | Патчи установленных линеек (`10.0.1xx`, `10.0.2xx`, `10.0.3xx`) по манифесту Microsoft |
| Разработка | Git | Команда `git` и пакет `Git.Git` (`winget`) |
| Разработка | Node.js | Активная `node` в пределах текущей major-ветки через владельца (`nvm` или `winget`) |

### Активный CLI и глобальный npm-пакет

В группах OpenAI и Anthropic активная команда из `PATH` (`Codex CLI`, `Claude Code`) и глобальный пакет npm (`Codex npm`, `Claude npm`) разнесены по разным карточкам. Команда `codex` или `claude` в терминале часто ведёт в нативный установщик, отдельную папку инструментов или shim-каталог, тогда как `npm install -g` обновляет пакет в глобальном префиксе Node.js. Разделение карточек сразу показывает, какая именно копия устарела и чем вы реально пользуетесь.

### Плагины и прямое обновление

Для карточек `Codex плагины` и `Claude плагины` предварительное сравнение версий недоступно: маркетплейсы плагинов не отдают единый реестр версий без фактического прогона синхронизации. Такие карточки получают статус **«Обновляется напрямую»**:

- после общей проверки галочка на них сама не ставится, чтобы не запускать лишнюю сетевую синхронизацию при каждом обновлении;
- если нужно подтянуть свежие версии плагинов, отметьте карточку вручную или выберите **«Обновить»** в меню `⋮`;
- команды **«Установить»** и **«Удалить»** для карточек плагинов отключены.

### Antigravity CLI и DeepSeek Harness

Доступная версия `Antigravity CLI (agy)` проверяется по манифесту официального установщика для архитектуры Windows x64 или ARM64. Если сервер манифеста недоступен или ответ повреждён, карточка переходит в **«Ошибка проверки»** и сохраняет уже найденную установленную версию вместо ложного статуса «Актуально».

`DeepSeek Harness (DSH)` проверяется и обновляется через глобальный пакет `@deepseek-ai/dsh`. Официальный пакет использует тег `latest`, в котором автор также публикует релиз-кандидаты (`rc`).

### Статусы карточек и меню действий

Карточка никогда не превращает сбой чтения версии в «всё обновлено». Состояния различаются по цвету индикатора и тексту:

| Статус | Что означает |
| --- | --- |
| `Актуально` | Установленная версия совпадает с последней доступной во внешнем источнике |
| `Есть обновление` | Найдена более новая версия; карточка автоматически отмечается галочкой после проверки |
| `Обновляется напрямую` | Инструмент установлен, но обновляется без предварительного сравнения версий (плагины) |
| `Не установлено` | Компонент не найден в системе; его можно поставить через меню `⋮` → **«Установить»** |
| `Ошибка проверки` | Источник версий не ответил, вернул неполные данные или обнаружен конфликт установок |
| `Выполняется...` | Сейчас идёт проверка, обновление, установка или удаление этого компонента |

Кнопка `⋮` в правом верхнем углу карточки открывает контекстное меню для одного компонента: **«Проверить»**, **«Обновить»**, **«Установить»**, **«Удалить»** и **«Что нового»**. При наведении курсора на карточку всплывает подсказка с временем последней проверки, путём к активной команде и диагностическим сообщением. Перед удалением любого компонента приложение показывает диалог подтверждения.

Последние результаты проверки сохраняются в `%LOCALAPPDATA%\AIUpdater\Logs\LastResults.json`. При следующем запуске окно сразу показывает сохранённую картину с датой прошлой проверки, а актуальные версии подтягиваются по кнопке **«Проверить всё»**.

## Инструменты разработки и защита окружения

Инструменты разработки тесно связаны с `PATH`, менеджерами версий и проектами, поэтому AIUpdater проверяет владельца установки перед каждым действием.

### Windows Terminal и источники winget

Для Windows Terminal используется пакет Microsoft Store:

```powershell
winget upgrade --id 9N0DX20HK701 -e --source msstore
```

Для остальных настольных программ используется источник `winget`. Если `winget list` для пакета из Store не возвращает доступную версию, результат считается неопределённым и помечается как **«Ошибка проверки»**, а не как подтверждение актуальности.

### Node.js: NVM и standalone

Перед проверкой и обновлением `Node.js` приложение определяет владельца активного `node.exe`:

- **Установка под управлением NVM**: обновляется через `nvm` в пределах текущей major-ветки; прямая установка и удаление через `winget` блокируются, чтобы не создать вторую конфликтующую копию Node.js в системе.
- **Standalone-установка**: обновляется через `winget` по идентификатору текущей major-ветки (`OpenJS.NodeJS.LTS` или соответствующей линии) без принудительного перевода на следующую major-версию.
- **Защита от скрытой автоустановки в NVM shim**: если `node` работает через shim-режим NVM, проверка требует отключённого параметра `auto_install`, чтобы обычное чтение `node --version` не скачивало отсутствующую версию в фоне.

### PowerShell 7

Если в `PATH` одновременно присутствуют несколько копий `pwsh` (например, штатный MSI/winget-пакет и устаревший `.NET global tool` в `~/.dotnet/tools`), карточка сообщает о конфликте установок. Копия, установленная как `.NET global tool`, не перезаписывается через `winget`, чтобы не оставить битый перехватчик в `PATH`.

### .NET SDK 10: патчи по линейкам без сноса

Стандартное обновление `.NET SDK` через `winget` в Windows нередко удаляет предыдущие линейки SDK или ставит только одну последнюю ветку, после чего проекты с закреплённым `global.json` перестают собираться. В AIUpdater карточка `.NET SDK 10` работает иначе:

1. **Обслуживание по установленным feature bands**: приложение находит все уже установленные линейки ветки 10 (`10.0.1xx`, `10.0.2xx`, `10.0.3xx` и далее) и для каждой сверяет последний стабильный патч в официальном манифесте релизов Microsoft (`releases.json`). Новые, ранее не установленные feature bands сами не добавляются.
2. **Подписанные установщики и проверка SHA512**: для системной `x64`-установки скачиваются официальные установщики Microsoft с обязательной проверкой хеша `SHA512` до запуска.
3. **Политика `RemovePreviousVersion = never`**: на время установки патча приложение выставляет в реестре политику сохранения предыдущих версий для `.NET 10`, а после завершения возвращает прежнее значение и его тип реестра.
4. **Проверка сохранности SDK и Runtime**: после установки скрипт сверяет список SDK и рантаймов со снимком до обновления, подтверждая, что закреплённые в `global.json` версии остались на месте. Снимки версий, политики и журналы установщиков сохраняются рядом с основным логом.

Если в системе установлено сразу несколько линеек `.NET SDK 10`, одиночные действия **«Установить»** и **«Удалить»** из меню карточки блокируются, чтобы не удалять и не ставить произвольную ветку наугад. Другие основные версии SDK (`.NET 8`, `.NET 9`), отдельные рантаймы, образы Docker и дистрибутивы WSL карточка не затрагивает.

## История изменений и перевод

Кнопка **«Что нового»** в шапке главного окна (или в меню `⋮` любой карточки) открывает отдельное окно с историей выпусков всех 17 компонентов.

- **Семнадцать официальных источников**: приложение загружает заметки о выпусках напрямую из GitHub Releases, реестров npm, манифестов Microsoft и официальных страниц документации провайдеров.
- **Локальный кэш на диске**: скачанные выпуски сохраняются в `%LOCALAPPDATA%\AIUpdater\Changelogs`. При открытии окна история читается с диска мгновенно, а кнопка **«Проверить новые»** докачивает свежие релизы в фоне.
- **Фильтрация и поиск**: слева расположен поиск по названию компонента и галочка **«Только установленные»**. У каждого релиза отображаются метки **«Свежий»**, **«Установлено»** или **«Новее установленной»**.
- **Резюме и перевод через Antigravity Flash**: по кнопке **«Обработать этот релиз»** (или **«Обработать заново»**) заметки о выпуске отправляются в локальный `Antigravity CLI (agy)` в безголовом режиме на модели Flash. ИИ переводит список изменений на русский язык и собирает короткое резюме по рубрикам (`Новое`, `Изменено и улучшено`, `Исправлено`, `Безопасность`, `Важно`).
- **Переключение оригинала и перевода**: готовый перевод кэшируется на диске. Кнопка в шапке окна или внутри карточки релиза мгновенно переключает текст между русским разбором и английским оригиналом.

## Журналы и масштаб интерфейса

Нижняя панель главного окна разделена на вкладки: **«Общий журнал»**, **«OpenAI»**, **«Anthropic»**, **«Google»**, **«DeepSeek»** и **«Разработка»**. Если во время пакетного обновления один из инструментов вернул ошибку, его вывод сразу виден в своей вкладке со счётчиком ошибок или доступных обновлений, не теряясь в общем потоке строк.

- **Где лежат файлы**: все журналы запусков, `LastResults.json` и снимки `.NET SDK` записываются в `%LOCALAPPDATA%\AIUpdater\Logs`. Кнопки **«Папка журналов»** и **«Открыть лог»** открывают каталог или текущий файл в один клик.
- **Масштабирование шрифта**: кнопки `A-` и `A+`, а также `Ctrl + колесо мыши` меняют размер шрифта в журнале выполнения (`8–24 pt`) и масштаб текста в окне «Что нового» (`80–160%`). Кнопка с процентами в окне истории изменений возвращает масштаб к `100%`. Выбранные размеры сохраняются в `%LOCALAPPDATA%\AIUpdater\ui-settings.json`.

### Запуск и локальная публикация

Для сборки требуется Windows и `.NET SDK 10.0.303` (закреплён в `global.json`). Приложение запускает проверки и обновления через Windows PowerShell и при старте запрашивает права администратора.

```powershell
dotnet run --project src/AIUpdater/AIUpdater.csproj
```

Собрать локальную папку в `publish/local`:

```powershell
dotnet publish src/AIUpdater/AIUpdater.csproj -c Release --self-contained false -o publish/local
```

Рабочие скрипты в подпапке `Scripts` рядом с `AIUpdater.exe` обязательны для работы приложения – не переносите `AIUpdater.exe` отдельно от папки публикации.

Для сборки с созданием ярлыка `AIUpdater.lnk` и команды **«Обновить AIUpdater.cmd»** на рабочем столе используйте:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File build/publish-local.ps1
```

Прежние файлы с рабочего стола при этом аккуратно переносятся в `artifacts/desktop-previous`.

### Автоматические проверки

Полный прогон всех проверок одной командой из PowerShell 7:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File build/verify.ps1
```

Или по отдельности:

```powershell
dotnet build AIUpdater.slnx
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Scripts/Verify-Updater.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Scripts/Verify-PackageChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/Scripts/Verify-DevelopmentTools.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File tests/Scripts/Verify-Release.ps1
dotnet run --project tests/AIUpdater.InterfaceChecks -- artifacts/interface-check
```

Все тесты работают на подставных ответах команд и изолированных данных: установленные в системе программы не затрагиваются, а контрольные снимки интерфейса сохраняются в `artifacts/interface-check`.

## Релизы

Номер версии хранится в `Directory.Build.props` в формате целого числа (`1`, `2`, `3`) или патча (`1.1`, `1.2`). В заголовке окна и Git-тегах к нему добавляется префикс `v` (`v2`, `v2.1`). Обе части номера положительные, без ведущих нулей, до `65534`.

Перед выпуском новой версии добавьте описание изменений в [CHANGELOG.md](CHANGELOG.md) под заголовком будущего номера (например, `## 3` или `## 2.1`), затем обновите версию скриптом:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File build/bump-version.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File build/bump-version.ps1 -Version patch
```

Первая команда переводит версию на следующее целое число (`2` → `3`), вторая – на следующий патч (`2` → `2.1`). Точный номер можно передать явно (`-Version 3` или `-Version 2.1`). Без непустого раздела в `CHANGELOG.md` скрипт версию не изменит. Коммит и отправку в GitHub скрипт сам не делает.

После отправки изменений в `master` workflow `CI` собирает решение и прогоняет тесты, а затем запускает workflow `Release`, который формирует архивы, собирает описание релиза из шаблона `.github/release-body.md`, раздела `CHANGELOG.md` и свёрнутого блока коммитов (`build/render-release-notes.ps1`), создаёт тег и публикует GitHub Release:

| Файл релиза | Назначение |
| --- | --- |
| `AIUpdater-v2-win-x64.zip` | Приложение и скрипты; требуется установленный .NET 10 Desktop Runtime |
| `AIUpdater-v2-win-x64-portable.zip` | Автономный архив: приложение, скрипты и встроенный рантайм .NET 10 |
| `SHA256SUMS.txt` | Контрольные суммы обоих архивов |

Собрать точно такие же релизные архивы локально в `artifacts/release` без публикации:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File build/package-release.ps1
```

## Завершение миграции рабочего окружения

Сценарий `build/Finish-DevelopmentMigration.ps1` подготовлен для локального профиля `C:\Users\admin` по результатам аудита среды разработки. Проверить план действий без внесения изменений:

```powershell
pwsh -NoProfile -File build/Finish-DevelopmentMigration.ps1
```

Для фактического выполнения закройте процессы Node/MCP, старый PowerShell из `.dotnet/tools` и Windows Terminal, после чего запустите `build/Finish-DevelopmentMigration.cmd` из Проводника обычным двойным щелчком (без «Запуск от имени администратора»). Если в памяти остались процессы Node, NVM или Windows Terminal, сценарий остановится, ничего не меняя. Занятый процесс PowerShell global tool откладывает только удаление самого global tool – остальные шаги выполняются, а пропуск фиксируется в `result.json`. Фоновый `deletion-canary-watcher.ps1` после согласованной остановки переведён на штатный PowerShell.

Что делает сценарий при выполнении:

1. Удаляет дублирующий PowerShell global tool и запускает подготовленный подписанный установщик NVM 2.0.1 с сохранением установленных версий Node и отключением `auto_install`.
2. Обновляет активную версию Node в пределах её текущей major-ветки и обновляет Windows Terminal через `winget upgrade --id 9N0DX20HK701 -e --source msstore`.
3. Проверяет работоспособность Node/npm, штатного PowerShell, регистрацию Terminal и неизменность двух проверенных файлов `global.json`.
4. Убирает дубликаты в `User PATH` с сохранением типа значения реестра (`REG_EXPAND_SZ` / `REG_SZ`). Если установлен нативный Codex, его каталог ставится перед NVM в `User PATH`, а `codex --version` подтверждает, что команда не перехвачена shim-обёрткой NVM.

Для работы нужны сохранённые установщик и резервные копии из `.kc/scratch/development-environment-normalization` и `.kc/artifacts/development-environment-normalization`, а также доступ к сети. Журналы, снимки `PATH` и `result.json` каждого запуска складываются в `.kc/artifacts/development-environment-normalization/deferred-*`. При сбое можно устранить причину и запустить сценарий повторно – он продолжит с сохранённого состояния. Старая MSI-регистрация Node была удалена после проверки её файловых ресурсов, а удалённая установщиком запись глобальных npm-команд в `User PATH` восстановлена на прежнем месте. Оставшиеся регистрации PowerShell и Visual Studio, а также операции с `claude-sync` и Python 3.13 перечисляются в отчёте как отдельная ручная работа.

## Чего не умеет

- **Работать на Linux и macOS** – интерфейс на WPF, интеграция с `winget`, Microsoft Store и реестром Windows рассчитаны только на Windows 10/11.
- **Обновлять программы тайком по расписанию** – у приложения нет фоновой службы или планировщика; проверку и установку всегда запускает пользователь.
- **Предсказывать версии плагинов до запуска обновления** – карточки плагинов работают в режиме прямого обновления по явному выбору.
- **Переводить Node.js на новую major-ветку или ставить новые линейки .NET SDK** – приложение обновляет только текущую major-линию Node и уже установленные feature bands `.NET SDK 10`.

## Частые вопросы

**Какой архив скачивать из Releases – обычный или `portable`?**
Если в системе уже стоит `.NET 10 Desktop Runtime` (или `.NET SDK 10`), берите компактный `AIUpdater-v2-win-x64.zip`. Если не хочется ничего доставлять отдельно – качайте `AIUpdater-v2-win-x64-portable.zip`, внутри уже есть рантайм. В обоих случаях распаковывайте архив целиком в отдельную папку.

**Зачем приложению права администратора при старте?**
Системные установщики `.NET SDK 10`, часть пакетов `winget` и обновление инструментов в системных каталогах требуют повышенных прав. Запрос один раз на старте избавляет от череды всплывающих окон UAC посреди пакетного обновления.

**Почему после нажатия «Проверить всё» галочки стоят не на всех карточках?**
Автоматически отмечаются только компоненты со статусом **«Есть обновление»**, где внешняя версия строго новее установленной. Карточки плагинов (**«Обновляется напрямую»**) оставлены без галочки намеренно, чтобы вы сами решали, когда тянуть обновления из маркетплейсов.

**Для перевода в окне «Что нового» нужен API-ключ?**
Нет. Обработка и перевод заметок о релизе вызывают уже установленный локально `Antigravity CLI (agy)` на быстрой модели Flash. Если `agy` не установлен, окно «Что нового» спокойно показывает оригинальные заметки о выпусках на английском языке.
